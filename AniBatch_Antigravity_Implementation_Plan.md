# AniBatch — Super Detailed Antigravity Implementation Plan

Yes. I researched the current Antigravity 2.0/IDE documentation and the supporting technologies. I would build this as a **proper downloader framework with pluggable providers**, rather than a single brittle scraping script.

Antigravity is well suited to this because it now supports implementation-plan artifacts, persistent project rules, reusable Agent Skills, isolated Git worktrees, and parallel subagents. Google specifically recommends using rules for architectural constraints and Skills for repeatable multi-step procedures; `/plan` can explicitly create a reviewable implementation plan.

One important boundary: the implementation below deliberately does **not** instruct Antigravity to defeat DRM, bypass authentication/paywalls/CAPTCHAs, or reverse-engineer protected streaming services. Provider adapters should target sources you are authorized to automate. Everything else—batching, metadata, episode matching, resume, quality selection, subtitles, muxing, retries, organization, UI—is included.

# 2. Architecture

Do **not** let Antigravity make something like:

```text
scraper.py
```

with 2,000 lines containing scraping, downloading, naming, database logic, and UI.

The architecture should instead be:

```text
                       ┌─────────────────────┐
                       │        CLI/TUI      │
                       │ Typer + Rich/Textual│
                       └──────────┬──────────┘
                                  │
                       ┌──────────▼──────────┐
                       │ Application Service │
                       │    DownloadService  │
                       └──────────┬──────────┘
                                  │
           ┌──────────────────────┼─────────────────────┐
           │                      │                     │
           ▼                      ▼                     ▼
 ┌────────────────┐    ┌─────────────────┐    ┌──────────────────┐
 │ MetadataService│    │ ProviderManager │    │ QueueManager     │
 │    AniList     │    │                 │    │                  │
 └────────────────┘    └────────┬────────┘    └─────────┬────────┘
                                │                       │
                       ┌────────▼────────┐              │

                       │                 │              │
                       │ search()        │              │
                       │ episodes()      │              │
                       │ streams()       │              │
                       └────────┬────────┘              │
                                │                       │
                  ┌─────────────┼──────────────┐        │
                  ▼             ▼              ▼        │
             Provider A    Provider B     TestProvider   │
                                                        │
                                    ┌───────────────────▼─────┐
```

AniList should supply canonical metadata rather than being treated as the video source. Its GraphQL `Media` queries support searching anime and retrieving media records.

# 3. Recommended stack

Use:

```text
Language          Python 3.12+
Package manager   uv
CLI               Typer
CLI rendering     Rich
Future TUI        Textual
HTTP              HTTPX
Models            Pydantic
Database          SQLite
Async             asyncio
Testing           pytest + pytest-asyncio
Mock HTTP         respx
Retry handling    tenacity
Metadata          AniList GraphQL API
Media processing  FFmpeg / ffprobe
Optional backend  aria2c
Configuration     TOML
Logging           Python logging / structlog
```

HTTPX is particularly suitable because it exposes asynchronous clients and asynchronous streaming using `aiter_bytes()`. Its documentation also recommends reusing clients rather than continually constructing clients inside hot loops, which Antigravity should follow in the architecture.

aria2 should be an **optional backend**, not a mandatory dependency. It already provides continuation of partial HTTP downloads and multiple concurrent jobs, which makes it useful when the user wants a stronger external download engine.

# 6. Provider abstraction

This is probably the most important architectural decision.

Antigravity must never make downstream code dependent on HTML selectors from one website.

Define something similar to:

```python
class Provider(ABC):

    name: str

    @abstractmethod
    async def search(
        self,
        query: str
    ) -> list[ProviderSeries]:
        ...

    @abstractmethod
    async def get_series(
        self,
        series_id: str
    ) -> ProviderSeries:
        ...

    @abstractmethod
    async def get_episodes(
        self,
        series_id: str
    ) -> list[ProviderEpisode]:
        ...

    @abstractmethod
    async def get_media(
        self,
        episode: ProviderEpisode
    ) -> EpisodeMedia:
        ...
```

The rest of AniBatch should only know about:

```text
ProviderSeries
ProviderEpisode
EpisodeMedia
MediaVariant
SubtitleTrack
```

and never:

```text
CSS selectors
HTML elements
site-specific IDs
site-specific cookies
provider URL structure
```

outside the adapter.

That gives you:

```text
Provider website changes
          ↓
Change one adapter
          ↓
Downloader unaffected
Database unaffected
CLI unaffected
Metadata unaffected
```


# 10. Native HTTP download backend

First implement plain authorized HTTP downloads.

Use:

```text
HTTPX AsyncClient
       ↓
HEAD / metadata request
       ↓
detect Content-Length
       ↓
detect Accept-Ranges
       ↓
create .part file
       ↓
stream chunks
       ↓
periodic progress event
       ↓
fsync / close
       ↓
verify
       ↓
atomic rename
```

Partial files:

```text
Episode 01.mkv.part
```

After successful completion:

```text
Episode 01.mkv
```

HTTPX supports asynchronous response streaming without loading the whole file into memory.

# 11. Resume system

On interruption:

```text
Downloaded:
428,392,448 bytes

Expected:
1,284,920,320 bytes
```

Next launch:

```http
Range: bytes=428392448-
```

If server returns:

```text
206 Partial Content
```

continue.

If it refuses ranges:

```text
200 OK
```

decide whether to restart cleanly.

Keep resume metadata in SQLite rather than relying solely on the `.part` filename.

# 12. Download queue

Implement:

```python
QueueManager(
    max_concurrent_downloads=3
)
```

Use an asyncio semaphore.

Example:

```text
Episode 01   downloading
Episode 02   downloading
Episode 03   downloading

Episode 04   waiting
Episode 05   waiting
...
```

When E01 finishes:

```text
Episode 04
```

automatically begins.

Make concurrency configurable:

```toml
[downloads]
concurrency = 3
```

Do not default to something excessive like 20.

# 13. Retry strategy

Retry only appropriate failures.

Retry:

```text
408
429
500
502
503
504

connection resets
timeouts
temporary DNS failures
```

Don't endlessly retry:

```text
401
403
404
invalid URL
unsupported content
DRM/protected source
```

Use exponential backoff:

```text
attempt 1 → 1 sec
attempt 2 → 2 sec
attempt 3 → 4 sec
attempt 4 → 8 sec
```

plus jitter.

# 16. FFmpeg wrapper

Do not scatter subprocess calls throughout the project.

Create:

```python
FFmpegService
```

with:

```text
is_available()

probe()

mux_subtitles()

mux_audio()

verify_container()

get_duration()
```

Every subprocess should use argument arrays rather than shell strings.

Good:

```python
subprocess.run(
    ["ffmpeg", "-i", input_file, ...]
)
```

Not:

```python
os.system(f"ffmpeg -i {filename}")
```

That avoids command-injection problems with unusual filenames.

# 26. Antigravity `AGENTS.md`

At the root, I'd give Antigravity something close to:

```text
# AniBatch Engineering Rules

## Architecture

Use clean layered architecture.

CLI code must not perform scraping, database access,
FFmpeg execution, or direct HTTP downloads itself.

Provider-specific logic must exist exclusively inside
src/anibatch/providers/.

No provider-specific types may leak into downloader,
metadata, storage, naming, or CLI layers.

All network operations must be asynchronous unless
there is a documented reason otherwise.

## Providers

Every provider must implement the Provider interface.

Never modify core downloader behavior to accommodate
one provider unless the behavior is genuinely generic.

Every provider requires contract tests.

Do not implement mechanisms designed to defeat DRM,
CAPTCHA, authentication, paywalls, or other access
controls.

## Downloads

Downloads must be resumable where the server supports
HTTP ranges.

Never write directly to final destination filenames.
Use temporary .part files followed by atomic finalization.

Queue state must survive program restart.

## Database

Database writes must go through the storage/repository
layer.

Schema changes require migrations.

## FFmpeg

All FFmpeg execution must go through FFmpegService.

Never invoke shell=True for media filenames.

## Testing

Every bug fix requires a regression test.

Network-based tests must not depend on public websites.

Provider behavior should be mocked or tested against
controlled fixtures.

Run the full test suite before declaring a task complete.

## Scope

Do not redesign unrelated modules while completing
a feature.

Prefer small, reviewable commits.

## Documentation

Any user-facing CLI option requires:
- help text
- README documentation
- at least one test
```

This is exactly the sort of persistent project guidance Google recommends putting in `AGENTS.md` or `.agents/rules/`.

# Final architectural recommendation

I wouldn't call the core project an **"anime scraper."**

Make the core application a:

**metadata + provider + download manager framework**

and make scraping/API interaction merely one implementation of:

```text
Provider
```

That distinction will make a large difference six months later. Sites change; download logic, queues, metadata models, file organization and your UI shouldn't need to change with them.

For Antigravity specifically, establish **`AGENTS.md` + `.agents/rules/` + 2–3 focused Skills before serious agentic coding begins**. The durable project workflow should revolve around Rules + Skills + Plan artifacts + subagents, rather than a monolithic one-shot build prompt.
